# CSS Layout — Reference

Deeper details that back the rules in `SKILL.md`. Source material: Polypane's "Understanding the fundamentals of CSS Layout" by Kilian Valkhof.

## Anonymous boxes and the whitespace bug

For `<p>This is <em>emphasized</em></p>`, the text "This is" is wrapped in an anonymous **inline** box (because `<em>` is inline). For `<div>This is <p>...</p></div>`, "This is" becomes an anonymous **block** box (because `<p>` is block).

The notorious gap between two `display: inline-block` siblings comes from an anonymous inline box generated by the whitespace (newline/spaces) between them. Fixes:

- Remove whitespace in HTML between the tags (fragile, prettier will reintroduce it).
- `white-space: nowrap` on the parent (forces same line but the gap remains, so total width still overflows).
- `font-size: 0` on parent and reset on children (works, but easy to forget the reset).
- Future: `white-space-collapse: discard` (not yet supported).
- **Recommended**: switch to flex or grid.

## Inline elements: lines, baselines, vertical-align

Each line of inline content has a baseline determined by the font. By default all inline boxes (including images and inline-blocks) sit on the baseline.

`vertical-align` values:

- `baseline` (default): bottom of the box on the line's baseline.
- `top` / `bottom`: top/bottom of the line box (depends on `line-height`).
- `text-top` / `text-bottom`: top/bottom of the text portion (font ascender/descender).
- `middle`: `baseline + (x-height / 2)` — NOT the geometric middle. Often appears low.

Margins/widths/heights don't affect inline elements (only inline-block does). For inline elements, decorations (border, padding) on a line that wraps are sliced by default. Use `box-decoration-break: clone` to repeat them on each line segment.

## Margin: auto — the four cases

The horizontal layout equation is:
```
container width = margin-left + border-left + padding-left + width + padding-right + border-right + margin-right
```

With `auto` values resolved by the constraint:

1. `margin: auto auto; width: auto;` → margins=0, width=100%.
2. `margin: 2rem; width: auto;` → width fills remainder: `100% - 4rem`.
3. `margin: auto; width: 50%;` → margins split equally (25% each).
4. `margin-left: auto; margin-right: 50px; width: 200px;` → left margin gets `100% - 250px` (pushes element right).

`margin: auto` does **not** vertically center in normal flow because the vertical layout doesn't use this constraint. It DOES vertically center an absolutely positioned element with `inset: 0` and a defined width+height.

## Margin collapse — full rules

Vertical margins collapse between block siblings, and between a parent and its first/last in-flow child, when no border, padding, inline content, clearance, or new BFC sits between them. Result is the larger of the two (or, for negative + positive: their sum).

To stop collapse, create a new block formatting context on the parent. In order of preference:
1. `display: flow-root` — explicit, no side effects.
2. `overflow: auto|hidden` — works but adds clipping/scrollbar potential.
3. Add `padding-top: 1px` or a border — works but changes geometry.
4. `display: flex|grid` — also stops it but changes layout algorithm entirely.

Inline (left/right) margins never collapse. Margins on flex/grid items don't collapse.

## Containing block — full rules

Where percentages resolve to and where positioned elements anchor:

- Static, relative, sticky elements: containing block is the **content-box** of the nearest block-level ancestor.
- `position: absolute`: containing block is the **padding-box** of the nearest **positioned** ancestor (any `position` ≠ `static`). If none exists, it's the initial containing block (≈ viewport at root).
- `position: fixed`: containing block is the **viewport** UNLESS an ancestor has `transform`, `perspective`, `filter`, `backdrop-filter`, `will-change` (with one of those), or `contain: paint|layout|strict|content` set to a non-default — those create a containing block for fixed descendants.

Percentage rules:

- `width`, `min-width`, `max-width` → % of containing block's inline size.
- `height` → % of containing block's block size IF that size is definite, else `auto`.
- `margin-*`, `padding-*` (all four sides) → % of containing block's **inline** size (yes, even `margin-top` and `padding-bottom`). This avoids infinite-loop sizing.

## All ways to create a stacking context

(From the spec, common ones first.)

- Root element (`<html>`).
- `position: fixed` or `position: sticky` (regardless of z-index).
- `position: relative|absolute` AND `z-index` ≠ `auto`.
- Flex or grid **item** with `z-index` ≠ `auto`.
- `opacity` < 1.
- `mix-blend-mode` ≠ `normal`.
- `transform`, `filter`, `backdrop-filter`, `perspective`, `clip-path`, `mask`, `mask-image`, `mask-border` ≠ `none`.
- `isolation: isolate`.
- `container-type: size | inline-size`.
- `will-change` listing any of the properties above.
- `contain: layout | paint | strict | content`.

Use `isolation: isolate` when you specifically want a new stacking context with no other visual side effect.

## Position: sticky — failure modes

Sticky needs all of these to work:

1. At least one inset (`top`/`bottom`/`left`/`right`) set.
2. A scrolling ancestor (the "scrollport"). The element sticks to that ancestor's edges.
3. The scrolling ancestor must be taller than the sticky element (otherwise there's no room to stick).
4. No ancestor on the path to the scrollport with `overflow: hidden|auto|scroll` that itself can't scroll — that intercepts and breaks sticky.
5. In grid/flex, the default `align-items: stretch` makes the item fill the cross axis, leaving no room to move. Set `align-self: start` (or change container's `align-items`).
6. The element must not be `display: contents` or out of flow.

## Display: outer / inner

Modern `display` accepts two values: `display: <outer> <inner>`.

- Outer values (how it relates to siblings): `block`, `inline`, `run-in`.
- Inner values (how its children lay out): `flow` (normal flow), `flow-root` (new BFC), `flex`, `grid`, `table`, `ruby`.

Common single-keyword equivalents:

| Single keyword | Two-value form |
|---|---|
| `block` | `block flow` |
| `inline` | `inline flow` |
| `inline-block` | `inline flow-root` |
| `flex` | `block flex` |
| `inline-flex` | `inline flex` |
| `grid` | `block grid` |
| `inline-grid` | `inline grid` |
| `flow-root` | `block flow-root` |

## Flex vs Grid alignment summary

Both share these properties:

- `justify-content` — distributes items along the **main** axis (flex) / inline axis (grid) when there's free space.
- `align-content` — distributes lines/rows along the **cross** axis (flex) / block axis (grid).
- `align-items` — aligns each item along the cross axis.
- Grid additionally has `justify-items` — aligns each item along the inline axis.
- Per-item overrides: `align-self`, `justify-self`.
- Shorthands: `place-content`, `place-items`, `place-self`.

Default values to remember:

- Flex: `align-items: stretch`, `justify-content: flex-start`.
- Grid: `align-items: stretch`, `justify-items: stretch`.

`align-content: center` on a plain block container (with a defined height) is supported across modern browsers and centers content vertically without flex/grid.

## Centering — the canonical solution

```css
.parent { display: grid; place-content: center; min-height: 100dvh; }
```

This vertically and horizontally centers the parent's contents in flex, grid, and (with `align-content`) block. The only requirement is that the parent has a defined size on the axis you're centering on; otherwise the parent collapses to its content and "centering" is a no-op.

## Quick lookup: which property breaks what?

| Property on ancestor | Side effect |
|---|---|
| `transform`, `filter`, `perspective`, `backdrop-filter` | New containing block for `position: fixed` descendants; new stacking context. |
| `overflow: hidden|auto|scroll` | New scrolling context (affects `position: sticky`); creates BFC. |
| `opacity < 1` | New stacking context. |
| `isolation: isolate` | New stacking context, no other effect. |
| `contain: layout|paint|content|strict` | Various containment, often creates stacking + containing block. |
| `display: flow-root` | New BFC; stops margin collapse. |
| `container-type: size|inline-size` | Container query context; new containing block for size queries. |
